# Jaipur

支持同屏轮流操作，以及通过 Portal 在两台设备上联机对战的静态网页游戏。

## 启动

直接用浏览器打开 `index.html`，无需安装依赖或构建。也可以在本目录运行：

```sh
python3 -m http.server 8080
```

然后打开 `http://localhost:8080`。同一局域网内的触屏设备可访问电脑的局域网地址和此端口。本地模式在每个浏览器保存独立对局；联机请从仓库根目录提供 HTTP 服务，以便加载 Portal SDK。

## 操作

选择拿货、交换、出售或拿骆驼；点击相应卡牌，最后确认动作。交换时根据选中的市场牌和手牌自动补足骆驼数量，并提示还需选择的手牌；自动计算也会考虑 7 张手牌上限。操作记录和交接提示会显示拿取、出售的商品种类与数量，以及交换时交出和换入的具体卡牌。动作完成后自动遮住手牌，交给另一位玩家再解锁。面对面坐时可开启玩家 2 操作区旋转。切到后台或刷新后也会遮住手牌。

右上角「明牌模式」在左右两侧竖向展示双方手牌（玩家 1 固定左侧、玩家 2 固定右侧），中间为市场、筹码与操作区；对方手牌仅供查看；开启后不再遮罩交接，也不旋转界面。关闭时立即遮住手牌。模式设置会保存在本机。

浏览器本地自动保存对局。隐私模式或禁用存储时可能无法保存。隐藏手牌用于同屏交接，不是防止对方通过开发者工具读取状态的安全机制。

## 规则依据

- [Space Cowboys 官方游戏页](https://www.spacecowboys-games.com/game/jaipur/)
- [出版社英文规则书](https://cdn.svc.asmodee.net/production-spacecowboys/uploads/2025/11/Rules-JAIPUR-12x17-Version-EN_BD.pdf)

访问日期：2026-10-20。游戏内提供中文规则摘要及来源。采用 55 张牌、38 枚货物筹码、18 枚奖励筹码和先获两枚印章获胜的规则。第一局随机先手；后续由败者先手。

补充约定：分数、奖励筹码数、货物筹码数均相同时，不发印章，加赛并轮换先手。此情形在所查规则书中未明确处理。奖励堆耗尽后不再补充。已获分值和骆驼数量只向当前玩家显示，局末公开。

使用 Game-icons.net 商品 SVG 图标，来源、作者及 CC BY 3.0 许可详见 [图标说明](icons/README.md)，没有复制原版插画。原游戏设计：Sébastien Pauchon。

## 公开信息辅助

右上角可开关辅助功能，默认开启。非明牌模式解锁后，对方玩家栏显示公开出售所得的货物分、各类实际领取的货物筹码数量，以及 3／4／5+ 张出售奖励筹码数量。奖励分按原始筹码分布的均值 2／5／9.2 估算，并显示保守范围；不读取对手隐藏奖励分或骆驼数量，骆驼结算另计 0 或 5 分。统计随动作累计并保存。

## 内部对局状态（v2）

完整状态保存在 `localStorage["jaipur-v2"]`，不读取旧格式存档。界面最近 8 条文字日志仅用于展示，不是历史数据源。

- `history.initial`：本局发牌后的完整状态，包括牌库顺序、双方手牌及骆驼、市场、各筹码堆和胜利印章。
- `history.events`：不截断的动作列表，记录动作序号、玩家、动作类型及选牌索引；`before` / `after` 保存动作前后完整状态。
- 事件 `public`：拿取、交出、出售的牌、领取的货物筹码种类与分值、奖励筹码类别、市场补牌顺序和文字说明。
- 事件 `private`：领取的奖励筹码类别及实际分值；完整快照同样包含隐藏信息。非明牌辅助只使用公开统计，不能直接展示内部快照或私密数据。
- 事件 `result`：触发局末时的结算，包括双方分数、骆驼奖励归属、胜者及结束原因。
- `previousRounds`：同一场对战中已结束各局的完整历史和最终状态，通过 `nextRound` 追加；新一场或重开创建新状态。

快照排除 `history` / `previousRounds`，避免递归膨胀；已完成的事件与归档视为只读，状态推进只追加记录。非法动作不会写入历史。刷新恢复完整数据，后续功能无需解析中文日志即可读取或回放动作。

验证：`node history.test.cjs`。

## Portal 双人联机

通过 HTTPS 或 localhost HTTP 打开游戏，点击「联网 → 创建房间」，在 Portal 登录后生成邀请链接，另一台设备打开链接并点击「加入邀请对局」。房主是玩家 1，访客是玩家 2，先手随机。无需修改或部署 Worker。

联机固定显示自己的手牌，关闭明牌和同屏交接；对方回合、断线、待确认或协商期间禁止行动。悔棋、重开对战及局末开始下一局均需对方同意。支持刷新重放、自动重连、主动离开后恢复、重置访客和关闭房间。本地存档与联机分开，返回本地时恢复原对局。

协议版本为 `jaipur-net-v1`，使用局 ID 派生确定性随机过程，同步行动而非完整历史快照，接收方验证版本、席位、回合、局面版本及规则。非法消息暂停对战，可重新同步。Portal 共同日志包含重建完整牌局所需的信息，不能防止开发者工具读取对手手牌和牌库；仅适用于诚信对战。

验证（仓库根目录）：

```sh
node game/jaipur/engine.test.cjs
node game/jaipur/history.test.cjs
node game/jaipur/online.test.mjs
node portal/tests/jaipur-browser.mjs
```

浏览器测试复用 Portal 的 Playwright / Miniflare 依赖，默认使用 `/usr/bin/google-chrome`，可通过 `CHROME_PATH` 指定。使用独立本地服务，不连接生产房间。

不显示或保存累计局数与局号，由玩家自行记录；读取本地旧存档时移除旧的局号字段。


### 面对面扫码配对

「联网 → 面对面扫码配对」使用与 Tacta 相同的 WebRTC 直连组件，无需 Portal 登录。双方连接同一 Wi-Fi／手机热点，互扫房主码与应答码，也可导入二维码图片。玩法、席位保密、协商悔棋／重开／下一局沿用现有联网协议。

面对面房间不会调用 Portal 邀请、访客重置或关闭 API，也不会记为可刷新恢复的 Portal 房间。刷新、关闭或退出后需重新配对；返回本地时恢复原存档。需要 HTTPS／localhost，受本地网络权限、网络隔离和后台断连影响。正常界面隐藏手牌，完整牌局仍可从共享日志重建，仅用于诚信对战。实体手机和热点尚待验证。

验证：`node portal/tests/boards-nearby-browser.mjs`（包含六款游戏真实二维码与 WebRTC 测试）。
