Quoridor 双人触屏游戏

打开方式
直接用现代浏览器打开 index.html，无需安装依赖或构建。
也可在此目录运行：python3 -m http.server 18765 --bind 0.0.0.0
然后打开 http://localhost:18765 。手机和平板可通过同一局域网内电脑的 IP 和端口访问。
默认双方在同一设备上轮流操作；部署 Portal 后可点击“联网”创建房间或通过邀请链接加入。
本地同屏模式保留 file:// 支持；联网需要 HTTPS 或 localhost HTTP。

操作
走棋：点带圆点的合法目标格。
放墙：点“放墙”，点棋盘交点选择位置，选横墙或竖墙，点“确认放墙”。
悔棋：撤回上一手，包括恢复墙数量；新一局会弹出确认框。
刷新：浏览器允许本地存储时自动恢复对局。file:// 下存储行为取决于浏览器。

layout.js 根据当前视口和操作区实际高度，选择棋盘面积更大的横排或竖排布局。
小窗口同步缩放界面；规则弹窗自动适配窗口，不产生滚动条。

联网模式
通信部署见 ../../portal/README.md。GitHub Pages 仅提供静态前端；Cloudflare Worker/SQLite DO 负责身份、房间与消息转发，不包含游戏规则。
房主经 Portal 登录后创建房间，生成一次性邀请，访客点击“加入邀请对局”认领第二席位。
初始先手、合法行动、胜负和悔棋协商均在浏览器处理；双方应使用相同游戏版本。
收到非法消息时，本地提示并暂停，不应用该消息；服务端不判罚。重新同步无法删除非法记录，必要时创建新房间。
悔棋与再来一局需要双方同意；认输会发送本地结束操作。
同一席位的新标签页接管旧连接。刷新按消息记录重放并恢复身份；清除浏览器存储后须重新授权。
本地存档与联网记录分开，退出联网后原本地对局仍可恢复。
新增 online-protocol.mjs：游戏消息的本地校验和重放。
验证：cd ../../portal && npm test；npm run test:browser（默认使用系统 Google Chrome）。

联网界面更新
悔棋、重开请求与处理结果、对方离线/恢复、认输和房间结束使用游戏内弹窗；× 或 Esc 仅关闭弹窗，不代表同意。暂时关闭协商弹窗后可点击“查看协商请求”继续处理。
联网菜单仅向房主显示邀请操作，访客不显示链接或复制按钮。邀请被认领、过期或房间结束后立即清空显示。
关闭房间后无需刷新，可直接创建新房间并生成新的邀请。主动离开会保留“恢复房间”入口；断线保留席位，如需换人，由房主重置访客席位。
待确认消息在连接终止时结束等待；旧连接和延迟 HTTP 响应不能覆盖新房间的界面状态。
在已打开的游戏页访问新邀请链接也会显示加入入口；切换正在连接的房间前需要确认。过期或已失效的邀请不保留重试入口。

权限入口
通过房间邀请进入时只能加入指定房间，不显示“创建房间”。普通入口的创建功能要求管理员或已注册普通密钥完成游戏授权；访客会话不能创建房间或进入 Portal 管理界面。
