# Splendor Duel

中文静态网页版，支持两人在同一触屏上轮流对战。纯 HTML、CSS 和 JavaScript，无构建、无后端、无运行时网络依赖。

## 运行

直接用浏览器打开 `index.html` 即可。也可以在本目录运行：

```sh
python3 -m http.server 8080
```

本机访问 `http://localhost:8080`；同一局域网的手机或平板访问 `http://电脑的局域网IP:8080`，两人在这台设备上操作。不同设备之间不会同步对局。

## 操作

- 点击 1–3 枚宝石，再点确认拿取；点选已选宝石可取消。必须连续、同一横线/竖线/斜线，不可跨空位或黄金。
- 点击珠宝牌查看费用，选择购买或预留；点击左侧等级牌堆可盲预留顶牌。
- 预留需在棋盘选择一枚黄金；购买时可调整用黄金代付哪些颜色。
- 使用特权、补充棋盘属于主要行动前的可选操作。先特权，后补充。一次可选多个不相邻的非黄金宝石，每枚消耗一个特权；特权拿取不触发三同色/双珍珠惩罚。
- 能力、皇室牌、超限弃宝石均有交互提示，须完成后才能换人。
- 本页采用公开预留牌玩法：双方预留牌始终展示，当前玩家可点击自己的预留牌购买。
- 对坐模式在宽度大于 650px 时旋转玩家 2 的共享桌面、操作栏及弹窗，并反向显示玩家 2 状态；窄屏不旋转。
- 每次有效操作自动保存到当前浏览器 localStorage。刷新可续玩，暂未结算完的能力也会恢复。新对局会替换存档；浏览器禁用存储时显示提示。

## 规则范围

实现基础版：67 张珠宝牌（30/24/13）、4 张皇室牌、25 枚宝石（五色各 4、珍珠 2、黄金 3）、3 个特权。包含双加成、叠色、额外回合、同色取宝石、拿取对手宝石、特权转移、第 3/6 顶王冠奖励、回合末 10 枚上限，以及总声望 20 / 王冠 10 / 同色声望 10 三种即时胜利条件。不含扩展。牌面和棋盘使用自行绘制的文字/CSS，不分发原版美术。

规则按完整的回合顺序结算：卡牌能力 → 皇室奖励及其能力 → 弃至十枚 → 检查胜利 → 下个回合。额外回合可累加。叠色牌只能选择已有珠宝加成的颜色；无加成的声望牌及皇室牌不计入同色声望。不能执行任何主要行动时，系统根据拿取、购买（含预留牌）、预留三类合法操作自动判断，突出显示“必须补充棋盘”。持有十枚宝石本身不会禁止拿取，仍在回合末弃回。

## 来源与核对

查询日期：2026-10-20。

1. [出版商 Asmodee 产品页](https://www.asmodee.ca/en/product/splendor-duel/)
2. [出版商英文规则 PDF](https://cdn.svc.asmodee.net/production-asmodeeca/uploads/2022/11/SCSPL2P01EN_Rules_Planche_BD.pdf) — 回合规则与胜利条件的主要依据。
3. [卡牌数值初始转录](https://github.com/BalthazarW/splendor-duel/blob/main/data/cards.data) — `cards-source.txt` 保留原始数值表，仅用于溯源；游戏使用 `cards.js`。
4. [Splendor Tactics 卡牌数据库](https://www.splendortactics.com/cards) — 对全部 67 张珠宝牌的等级、费用、声望、加成颜色/数量、王冠、能力逐项交叉核对。
5. [实物卡牌扫描核对](https://note.com/bousicom/n/n4de9aae60a69) — 只用于检查差异，不包含其图片。

6. [出版商维护的 Dized 官方规则与 FAQ](https://rules.dized.com/game/W-CkaRFlR36L6fiDQiWcHQ/faq) — 本轮用于交叉核对特权顺序、叠色、预留及无色声望。

**已修正原始转录中的错误：** 五张三级 4 声望牌不带王冠；初始表误记为 2 王冠。已经由卡牌数据库与实物扫描双重核对，`cards.js` 中均为 0，且有回归测试。其他 62 张珠宝牌的功能数值与独立数据库相符。三级 3 声望叠色牌同时具有额外回合能力，不能仅按单一能力枚举判断是否叠色。

## 测试

```sh
node --test engine.test.js
```

32 项测试覆盖规则边界、支付、预留、各类能力、皇室门槛、弃宝石、三种胜利条件、牌库数据修正，并自动执行 20 局对战：每次操作验证 67 张卡和 25 枚宝石守恒，每局均须抵达胜利。

浏览器验收覆盖：连续取宝石、玩家交接、特权、黄金预留、双方预留牌公开展示、购买支付、同色能力、刷新续玩，以及手机和平板布局。浏览器验证通过本地 HTTP 服务完成；自动化浏览器不允许访问 file URL，直接双击打开方式未实测。实际触屏硬件的多指事件未测试；交互使用原生按钮点击，不依赖悬停、拖拽或鼠标专属事件。

## 文件

- `index.html`、`style.css`：界面及响应式布局。
- `cards.js`：核对后的完整珠宝牌功能数值。
- `engine.js`：无 DOM 依赖、不可变状态转换的规则引擎。
- `app.js`：触控交互、公开预留牌、自动存档。
- `engine.test.js`：规则与整局测试。

## 基础版规则覆盖清单

本轮范围为完整基础版，不加入《The Counterfeiters》扩展或自定义规则。

| 官方规则 | 实现与核验 |
| --- | --- |
| 初始化与组件 | 67 张珠宝牌、4 张皇室牌、25 枚宝石；展示 5/4/3 张；随机先手，后手 1 特权 |
| 特权阶段 | 可使用多个；位置不限；允许珍珠，不许黄金；补充后禁止使用 |
| 补充棋盘 | 袋中洗混，从中心按螺旋填空；保留原宝石；对手获特权；袋空禁止 |
| 无合法主要行动 | 同时检查拿取、预留、购买（含预留牌）；无操作时必须补充，不能跳过回合 |
| 普通拿取 | 1–3 枚连续横/竖/斜线；不跨空位或黄金；三同色/双珍珠给予对手一个特权 |
| 预留 | 必须获得一枚棋盘黄金；公开牌或任一级顶牌；上限三张；未购牌无效果也无罚分 |
| 购买与支付 | 使用已有永久折扣；不降低珍珠费用；黄金可替代任意颜色，玩家可调整支付组合；费用可降为零 |
| 双加成与叠色 | 双加成减两枚；叠色只能选已有颜色，增加一个加成，不复制旧牌能力或双加成 |
| 卡牌能力 | 同色宝石由玩家选具体位置；拿对手非黄金宝石（含珍珠）；无目标自动略过；获得特权；额外完整回合 |
| 特权公共供应 | 公共池不足则从对手处取；已有三个不再增加 |
| 皇室牌 | 达到或跨过第三、第六顶王冠各选一次，共最多两张；立即结算能力，不占主要行动 |
| 回合末上限 | 临时超过十枚合法；完成卡牌与皇室能力后，玩家选择弃回至十枚（可弃黄金） |
| 三种胜利 | 20 总声望、10 王冠、任一颜色 10 声望；全部结算和弃牌后判定，无对手补偿回合；显示同时满足的条件 |
| 无色与皇室声望 | 只计入总声望；叠色牌声望计入所选颜色；预留牌不计分 |
| 牌库耗尽 | 买走或预留后的市场位置不再补牌；已空牌堆不能盲预留 |
| 公开信息与存档 | 双方宝石、加成及每色声望公开；预留牌公开展示；能力、皇室选择和弃宝石中途可保存恢复 |

新增边界用例使用合法操作检查器验证必须补充条件，并检查批量特权的原子性：选择错误时不会扣除部分特权或拿走部分宝石。
